# 『渋滞ほどき』引き継ぎ資料（Claude Code 向け）

最終更新: 2026-11-27

## 概要
大渋滞の街を、予算内の道路工事でほどく交通パズル。PC（マウス＋キーボード）前提。
車は行き先（出入口のグループ）ごとに、混雑込みの所要時間が最小の道を自分で探して走る。
「本番テスト」（ゲーム内2時間＝120秒、交通量は 0.75→1.2→0.75 の山型）で渋滞度を計測し、目標以下ならクリア。

## ファイル
- `index.html` … 本体。単一ファイル・ビルドなし。`<script>` は2ブロック固定（0=ロジック、1=UI）。テストがこの前提で読む
- `og.png` … `node tests/og.js` で再生成できる
- `tests/run.sh` … 一括検証（ロジック＋バランス、Playwright で通しプレイ）
- `tests/solutions.js` … 各ステージの想定解。`pass: true` の解が予算内でクリアできることを `check.js` が検証
- `tests/heat.js` … `node tests/heat.js s3 flyWest` のように、どこで車が止まっているかを ASCII で表示（調整用）

## シミュレーションの要点（ブロック0）
- 30×20 マス。道路はマス＋隣接マスとの「つながり」（link のビット）で表す。ドラッグで引いた隣どうしだけがつながる
- 車は辺（マス→隣のマス）の上を位置 s∈[0,1] で走る。車線ごとに追従（GAP, HT）。拡幅マスどうしの辺は2車線
- 交差点（つながり3本以上）は停止線 STOP で許可を待つ。動線（進入方向×退出方向）の衝突表 CONF で、ぶつからない向きは同時に通す（左側通行）。1秒以上待った車の動線と衝突するものは後回し（飢餓防止）
- 踏切は一時停止（0.45秒）＋遮断機。連続した踏切マスはまとめて渡る
- 立体交差は直進のみ（経路探索で右左折を禁止）。線路上の道路は跨線橋（elev）
- 経路：行き先ごとに「マス×進入方向」の後ろ向きダイクストラを1秒ごとに計算。止まっている車が多い辺・待ち台数の多い交差点/踏切ほど高コスト。3秒以上止まった車は経路を引き直す
- 30秒止まり続けた車は諦めて消える（集計あり）。本番テストは乱数シード固定で、同じ設計なら同じ結果
- 渋滞度 = （止まっている車＋入口で入れない車）の台数×時間 ÷ （走行中＋入れない車）の台数×時間（開始10秒以降）
- ★：クリア／渋滞度が目標の半分以下／予算を3割以上残す

## 調整した数値の目安（`node tests/check.js` の出力）
| ステージ | 工事前 | 想定解 |
|---|---|---|
| 1 駅前の朝ラッシュ | 48% | 南の道から駅へ新しい入口 0% |
| 2 川向こうのニュータウン | 55% | 北に2本目の橋 6% |
| 3 開かずの踏切 | 86% | 西の踏切を跨線橋＋東の踏切を撤去 21%（跨線橋だけだと35%） |
| 4 都心の大交差点 | 43% | 中央を立体交差 13% |
| 5 花火大会の帰り道 | 80% | 2本目の橋＋跨線橋＋駅への別ルート 15% |
