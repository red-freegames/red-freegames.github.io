## 1. ゲーム概要

- **タイトル**: 『ダンシングマニア』（確定）
- **一言で**: 変な踊りが人から人へ感染していく3Dブラウザゲーム。プレイヤーは「患者ゼロ」（最初に踊り出す1人）となり、制限時間内に広場の全員を踊らせる。警備員がプレイヤーを捕まえに来て、踊る人を説教で正気に戻す。
- **モチーフ**: 1518年にストラスブールで実在した「ダンシングマニア」（1人の女性から始まり1ヶ月で400人が踊り続けた集団ヒステリー事件）。
- **状態**: **公開済み** https://red-freegames.github.io/dancing-mania/ （RED FREE GAMES トップページにも掲載）。
- **ソースの置き場所**: 公開ブランチ（main）の `dancing-mania/` には **index.html と og.png だけ**を置く（サイトはリポジトリ内の全ファイルが公開されるため）。部品ファイル・build.py・テスト・この HANDOVER.md は **`dancing-mania-src` ブランチ**の `dancing-mania/` にある。
- **プラットフォーム想定**: スマホ+PCブラウザ。単一HTMLファイルで GitHub Pages に置く想定（作者の他作品と同じ形式）。

## 3. アーキテクチャ

- core は `globalThis.__DM__ = { STAGES, CFG, ARENA, createGame, rankFor, mulberry32 }` を公開。
- `createGame(seed)` がゲーム状態オブジェクト G を返す。乱数は mulberry32（シード固定で決定的）。
- ループ: UI が毎フレーム `G.update(dt, input)` を呼び、発生したイベントを `G.drainEvents()` で回収して演出に使う。
  イベント種別: `stage / infect / cure / catch / fever / clear / goal / over`。
- UI は `globalThis.__DM_UI__ = { get G(), setupStage }` を公開（スモークテスト用）。
- 座標系: 地面は XZ 平面、移動可能範囲は ±27 の正方形（`ARENA=27`）。角度は `atan2(x, z)` 形式（+Z向きが0）。

## 4. ゲーム仕様（数値は dance-core.js の CFG / STAGES が正）

### ルール
- プレイヤーは常時踊っている。踊っている人（プレイヤー or 感染者）の半径 **3.0** 以内に約 **0.7秒** 居た通行人が感染して踊り出す（「頑固な人」は **1.8秒**、黒っぽい服が目印）。
- 感染者はゆっくり移動しながら周囲を感染させる。最後の感染から **2.5秒** 以内の連続感染は「連鎖」としてカウント（HUDに残り時間ゲージ表示）。
- **フィーバー**: 連鎖が **12** に到達すると **5秒間**、感染範囲×1.5・感染速度×1.6。警備員も踊り出して無力化（追跡・説教なし）。
- **人だかり**: 各ステージに屋台が3〜5箇所あり、周囲に通行人の約45%が固まって立っている（頑固な人は入らない）。感染の着火点。
- **警備員**: プレイヤーが半径11以内に入ると追跡（速度7.0、プレイヤーは9.4）。接触でハート−1（全3個、捕獲後は2.5秒無敵＋警備員は持ち場へ帰還）。プレイヤーが遠い時は最寄りの感染者に近づき、2.2以内で2秒説教すると正気に戻す（戻った人は5秒間再感染免疫）。
- **勝敗**: 全員を同時に踊らせたらステージクリア（即時）。ハート0か時間切れでゲームオーバー。全3ステージ制覇で全クリア。
- **スコア**: 感染1人 = 100 + (連鎖数−1)×30。クリアボーナス = 残り時間×10 + ハート×200。

### 群衆の描画（インスタンス描画）
- 通行人は makePerson を使わず、部位ごと（脚L/R・胴・腕L/R・頭・DJのヘッドホン・新婦のドレス・影・円の輪/塗り）に `THREE.InstancedMesh` を1つずつ持つ（`CROWD`）。描画の呼び出しは人数によらず部位の数だけ。
- 姿勢は makePerson と同じ構造の骨組み `RIG`（Object3D のみ）に dancePose/walkPose/idlePose を当て、各部位の `matrixWorld` を `setMatrixAt` でコピーする（`syncCrowd`）。踊りの関数はプレイヤー・警備員と共通のまま。
- 服・ズボン・肌の色は `setColorAt`（`setupCrowdColors`、ステージ開始時）。**instanceColor は setColorAt の初回に「その時の count 分」だけ作られる**ので、count を0にする前に NPC_MAX 分作っておくこと（逆にすると全員真っ黒になる）。
- 頭上の♪（40個）と💢（16個）は使い回しのスプライト。
- プレイヤー・警備員・楽団は人数が少ないので従来の makePerson のまま。

### ステージの足し方
1. `dance-core.js` の `STAGES` に1件足す（`gimmick` と、その仕掛けの数値）。新しい仕掛けなら `update` の「ステージの仕掛け」に処理を足す。障害物は `obstacles: [[x, z, 半径]]` だけで動く。
2. `dance-ui.js` の `THEMES`（色と周りの景色）・`STAGE_HINT`（開始時の一言）・`gimmickText`（HUDの1行）・`buildWorld`（舞台装置）に1件ずつ足す。**4つとも STAGES と同じ順**。
3. `tests/harness-gimmicks.js` に仕掛けのテストを足す（ステージ番号は `SI.<gimmick>` で引く）。
4. 4本のテストを通し、基準値を下に書き直す。

### ステージの仕掛け（dance-core.js の STAGES.gimmick / CFG）
- **電車（駅前広場）**: 26人のうち8人は最初「電車の中」（state `away`）。経過12秒・27秒に4人ずつ北の改札（`CFG.gate`）から出てくる。未到着の人も総数に含むので、**全部の電車が着くまでクリアしない**。電車は着く2秒前に滑り込み、2.5秒停車して去る（UI の `updateTrain`）。
- **新郎新婦（披露宴）**: 北の高砂席（`CFG.coupleTable`）に立つ2人（kind `bride`/`groom`、頑固扱い=1.8秒）。どちらかが踊り出すと、その瞬間に半径9（`coupleBurstR`）以内の通行人が一斉に感染する（各1回だけ、`burstUsed`）。人だかりは高砂席から10以上離して配置。
- **やぐらと太鼓（夏祭り）**: 中央にやぐら（障害物、半径2.6）。普通の通行人の7割（`orbitRatio`）がやぐらの周りを半径7〜13で反時計回りに歩く（人だかりは25%に減らしてある）。6秒目から9秒ごとに太鼓が鳴り、2.4秒間は**全員の感染範囲×1.45**（`drumMul`、円も大きくなる）。
- **にわか雨（商店街）**: 8秒目から、7秒の雨と12秒の晴れを繰り返す。雨の間、踊っていない通行人（人だかりの人以外）は左右4か所のアーケード（`shelters`）へ走って、その下で固まる。雨が上がると散る。画面は暗くなり雨が降る（UI の `updateWeather`）。
- **動く歩道（空港）**: 2本（z=−9 は東へ、z=+9 は西へ、速さ6）。乗った人は**プレイヤーも通行人も警備員も**流される。人だかりは歩道の上に置かない。
- **楽団（大聖堂前）**: 3人の楽団が半径15の円を速さ2.4で回る。楽団は感染源（半径5）で、感染も説教もされない。中央に噴水（障害物）。元ネタの史実（踊りを止めるために楽団を雇ったら逆効果だった）から。
- **昼休み終了（オフィス街）**: 経過40秒（`bellAt`）でチャイム。以後、踊っていない通行人は全員、北の2つの入口（`CFG.doors`）へ速さ2.6で向かう。入口に入られると（state `gone`）総数から外れ、**残り時間 −3秒**（`escapePenalty`）。入口での待ち伏せが対抗策。

### 特別な通行人（kind）
- **DJ**（緑の服+ヘッドホン）: 踊ると感染範囲×1.7（`djRMul`、円も大きく描く）。歩き1.4・踊り1.0とゆっくり。
- **子ども**（体が0.68倍）: 歩き3.6・踊り3.0と速く、向きをよく変える。感染すると遠くまで広げる。
- 番号の割り当て: 0〜頑固数-1 が頑固な人、その後ろに DJ → 子ども →（披露宴なら）新郎新婦。特別な人は人だかりに入らない。

### 踊りの解放（DANCES）
ベストスコア（localStorage `dm_best`）で解放。選んだ踊り（`dm_dance`）は**全ダンサーが踊る**のでシンクロは維持。効果は控えめ。
| 踊り | 解放 | 効果 |
|---|---|---|
| へんな踊り | 最初から | なし |
| ロボットダンス | 150,000（かけだしダンサー） | 自分の感染範囲 +12% |
| 盆踊り | 400,000（広場のスター） | 連鎖の猶予 +0.8秒 |
| ツイスト | 750,000（踊りの感染源） | 移動速度 +8% |
| マニアの舞 | 1,100,000（ダンシングマニア） | フィーバー時間 +2秒 |
タイトルと結果画面で選べる。結果画面で新しく解放された踊りを知らせる。

### 称号（rankFor / RANKS）
1,100,000〜「ダンシングマニア」/ 750,000〜「踊りの感染源」/ 400,000〜「広場のスター」/ 150,000〜「かけだしダンサー」/ それ未満「ただの通行人」。人数増で連鎖が130前後まで伸びるため引き上げた（ボットの最終スコア中央値 ~100万、最大 ~118万）。踊りの解放ラインは称号のラインと同じ値を参照している。

### 連鎖モード「波」（試作・A/B比較中）
HOME の「連鎖モード」で切り替え（localStorage `dm_wave`、URL `?wave` でも可）。既定は「いつもの」。`createGame(seed, { wave: true })`。
- **パルス**: 新しく踊り出した人は `waveDelay`(0.2秒) 後に1回だけパルスを出し、円の中の通行人を**即座に**踊らせる。その人がまたパルスを出すのでドミノのように波が広がる。説教でパルス前に戻された人は出さない。頑固な人はパルス1回で半分（`waveStubbornHit`、2回で踊る）。「近くにいる」感染はいつもどおり残る（`waveDancerRate` = 1）。
- **波の記録**: 同じパルスからつながった人は同じ `waveId`。`G.waveSize`、`G.maxWave`、`G.stats`（player / pulse / dancer / other）で調整用に数えている。
- **演出（UI、波モードのみ）**: パルスの輪（波が15人以上で金色）、感染音はペンタトニックで上がり踊りの半拍に合わせて鳴る（同じ拍は2音まで）、連鎖表示は10/20/30で段階的に派手に、波が15/30/45人で「大連鎖！」「伝説の波！」「踊りの大災害！」と0.55秒のスロー、大きな波の間はカメラを引く、クリア時は全員の決めポーズを1.6秒見せてから結果へ。踊りの時計は `animT`（スロー中は遅くなる）。
- **基準値（harness-wave、ボット30回、人数増後）**: いつもの → 全制覇15・最大連鎖中央値133・プレイヤーが直接踊らせた割合43%。波 → 全制覇12・最大連鎖126・波の最大人数中央値35・直接23%。
- **今後**: 連鎖が続きすぎないよう調整予定（作者）。調整の候補は `waveDelay`（波の速さ）、`wavePulseMul`（パルスの大きさ）、波ごとの上限など。次の段階は人数増（インスタンス描画化）と配置の調整。

### HOME
- 起動時は HOME 画面（`#home`、旧タイトル画面）。右上に「🎮 他のゲームを見る」。
- プレイ中は左下に「🏠 HOME」ボタン（右下の音ボタンと対）。クリア画面・結果画面にも HOME ボタン。
- プレイ途中（phase が play / clear）で HOME を開くと**一時停止**（UI の `paused`。core の update を呼ばないだけ）。「▶ 続きから」で再開、「最初からはじめる」は確認画面（`#confirmPanel`）を挟む。途中で開いた HOME は説明文を畳む（`#home.inrun`）。
- プレイ途中に踊りを選び直しても、効果も見た目も次にはじめる時から（今の回は変わらない）。

### ステージ選択
到達した最大ステージ（localStorage `dm_reach`）までは、タイトルでスタート地点を選べる（初回は非表示）。途中から始めた場合、スコアは0から数え直し（それより前のステージの点は入らない）、結果に「（STAGE n から挑戦）」と出す。HOME の表記は「どこから始める？」「STAGE n ○○ から始める（スコアは0から数え直し）」。リトライも同じ地点から。

### 踊り（dance-ui.js の dancePose が正）
- 全ダンサーが**グローバル位相 `p = t × 9.0` を完全共有**し、寸分違わずシンクロするのが本作のキモ。個別位相に変えないこと。
- 8拍サイクル内の仕掛け: 1拍目=両手上げの決めポーズ / 5〜6拍目=左腕の風車回転+右腕の羽ばたき（へんな踊りのみ） / 8拍目=変なポーズで全員フリーズ。
- 踊りの型は `GROOVES`（basic/robot/bon/twist/mania）。**1拍目の決めポーズと8拍目のフリーズ、16拍の回転は全型共通**。型ごとに変わるのは残りの拍の動きだけ。
- 16拍に1回、全員同時にその場で1回転（`danceSpinOffset`）。
- 関節は数式駆動のプロシージャルアニメーション。モデルデータ・外部アセットは一切なし。

### 描画まわりの決まり事（作者の指摘で確定した事項。戻さないこと）
- **感染範囲の円と影は「地面専用グループ groundG」の子**。キャラ本体（root）に入れると踊りの傾き・跳ねで円が歪んで見えるため分離した。本体は root、地面物は groundG、両方を syncPersons で位置同期する。
- 円の見た目: 主人公＝太い輪（幅0.38）+不透明度0.6+明滅 / 他キャラ＝細い輪（幅0.18）+不透明度0.18+内側の塗り0.03。人数が多いと重なって見づらいため他キャラ側は意図的に薄い。
- 警備員は**蛍光イエロー（0xffd400）の服+白い反射帯+同色キャップ**。一般客のパレットに無い色で即判別させる確定仕様。
- プレイヤーは赤シャツ+金ズボン+頭上に▼マーカー。
- 結果画像は WebGL キャンバスのスナップショットを使うため `preserveDrawingBuffer: true` が必須（外すと結果画像が真っ黒になる）。

### 操作
- ドラッグ = 仮想スティック（指を置いた所が中心。半径46pxを超えると中心が指に追従、デッドゾーン12px、方向のみで常に全速）/ WASD・矢印キー。2本目の指は無視。pointercancel・blur・visibilitychange で入力を解除（動きっぱなし防止）。
- 音は iOS 対策で、ボタン押下・画面タッチの中で AudioContext を生成/resume（unlockAudio）。捕獲・フィーバーで振動（対応端末のみ）。
- 音は WebAudio の簡易シンセ。ON/OFF は localStorage `dm_sound`。

## 6. 開発履歴（作者のフィードバックと対応）

1. 初版: 3D試作（22/32/44人、90/105/120秒）。「インベーダーみたい」とは別ゲーム（5秒ストップ）への感想。

3. 警備員を蛍光イエロー化。
4. 円の視認性: 太く・濃く・内側の塗り追加 → その後「円が踊りで歪む」指摘で groundG 分離。
5. 連鎖強化一式: 連鎖タイマー可視化、人だかり、フィーバー、人数増（26/38/52）、制限時間を 60/70/90秒 に再調整、称号ライン引き上げ。

7. スマホ最適化: 縦持ちで画角を広げカメラを引く（fitCamera: 縦横比1:2でfov 50→64・距離×1.28、横長は従来どおり）、仮想スティック表示、iOS音声アンロック、セーフエリア（ノッチ）対応、小画面/横持ちのパネル・HUD縮小、ピンチ/ダブルタップ拡大の抑止、重い端末で解像度を自動で下げる（adaptQuality）。ゲームロジック（dance-core.js）は無変更。
8. 遊びの追加: ステージの仕掛け（電車・新郎新婦・昼休み終了）、特別な通行人（DJ・子ども）、踊りの解放（5種、ベストスコアで解放）。タイトルの遊び方は折りたたみ（縦に余裕のある画面では最初から開く）にして、小さいスマホでも開始ボタンがスクロールなしで見えるようにした。

## 7. 注意・未決事項

- タイトルは「ダンシングマニア」で確定（「（仮）」は外した）。キャッチコピーは「変な踊りは、感染する。」。
- 公開済み。OGP 画像は `og.png`（1200×630、夏祭りステージで全員が踊る場面にタイトルを重ねたもの）。X 共有文には `&url=` でゲームの URL を付けている（`GAME_URL`）。
- ほかの作品と同じく、AdSense のスクリプトを head に入れ、タイトル画面と結果画面に「他のゲームを見る」リンクと「実況・配信・動画投稿・収益化OK」の表記を入れている。
- 固有名詞（特定作品のスタンド名など）は使わないこと。時間停止ではなく踊りが題材だが、元ネタ作品への直接言及も避ける方針。
- パフォーマンス: 通行人は最大140人をインスタンス描画（部位ごとに1回の描画）。ソフトウェア描画の Chromium では 130人で18fps・80人で28fps（旧52人版は25〜28fps）。pixelRatio は PC最大2・タッチ端末最大1.75。プレイ中の平均フレームが 1/45秒を超えると 0.25 ずつ 1.0 まで下げる（上げ直しはしない）。スマホ実機での確認は未実施（Playwright の iPhone エミュレーションでは確認済み）。
- バランスの最終調整は作者の実機試遊フィードバックを待ってから。特に警備員の圧と制限時間は触り心地依存。
